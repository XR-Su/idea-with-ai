# 拾念 · Idea with AI

一个个人灵感工作台。在电脑或手机浏览器里接住想法，与 AI 沿同一条会话逐步讨论，再手动整理为可执行方案。

## 运行

需要 Node.js 22.12+（开发使用 Node.js 24）。

```bash
npm ci
npm run dev
```

打开终端显示的本地地址。开发服务绑定 `0.0.0.0`，手机与电脑连接同一局域网后，可以使用终端列出的 Network 地址访问。两台设备的浏览器数据相互独立。

```bash
npm test        # Vitest 单元与 React 组件测试，不使用 Playwright
npm run build  # TypeScript 检查与生产构建
npm run preview
```

`dist/` 可由任意静态 Web 服务托管，无需应用后端；Vite 使用相对资源路径，支持子路径部署。浏览器记录按站点来源（协议、域名、端口）隔离，更换访问地址前可用 JSON 备份迁移。

## 使用流程

1. 在工作台写下一句话，选择“先记下来”，或直接“与 AI 一起梳理”。也可以创建空会话再输入。
2. 在 **AI 设置** 选择 DeepSeek 或 MiniMax，填写自己的 API 密钥。默认不持久保存密钥；“记住”是显式选项。
3. AI 在信息模糊时追问，清晰时直接分析。你可以随时要求直接给出方案。每个灵感只有一条持续会话，未发送输入自动保存在本地。
4. 点击 **生成归档草稿**，检查和编辑方案，然后 **确认归档**。草稿本身不会产生版本，关闭后可继续编辑。
5. 第一次归档生成 V1，继续讨论后再次归档生成 V2、V3……归档不会结束或重置会话。
6. 在 **方案版本** 切换查看任意版本、修改其标题和正文。保存修改仍是原版本号，保留原归档时间，记录最后编辑时间。版本编辑不修改讨论快照。
7. **讨论快照** 是归档所依据的只读会话记录。不能回到历史版本分叉讨论，“继续当前会话”始终打开完整的当前时间线。AI 上下文使用当前完整讨论及最近版本当前编辑后的方案，不发送其它灵感或旧版本快照。
8. 每个版本可单独导出 Markdown，默认仅方案，可选附带对应讨论快照。完整 JSON 备份包含会话、未发送输入、全部版本和待确认草稿，不包含密钥；恢复时合并数据，有差异的相同 ID 保留为恢复副本。

若草稿生成后新增讨论，需按最新讨论重新生成草稿后再归档，避免版本与快照遗漏新内容。尚未发送的输入不会提交给 AI 或归入快照。

## 思维模式

完整设计、实现方式和扩展说明见 [思维模式实现归档](docs/thinking-modes.md)。

会话输入框上方的浅色设置区提供 **思维模式** 和 **回应模式** 两个下拉框，可独立组合默认／教员与静默／简洁／详细。两条模式说明统一显示在设置区，输入区使用独立的白底边框。每个灵感保存自己的选择，新灵感始终使用默认模式。

教员模式使用 `skills/mao-selected-works/SKILL.md` 和配套方法库、速查表、术语表、四卷参考资料，结合实际情况、关键矛盾、行动与验证分析现实问题。回答根据问题复杂度调整，信息不足时追问，区分原著观点、现代应用、事实和推断。当前没有接入 EPUB 原著，准确引文和页码需提供原著核对。

切换只记录位置，不自动请求 AI；后续回答继续使用完整讨论，并标记当时的思维模式。切回默认后不再附带教员资料，历史回复保留原样。静默模式仍只记录内容，主动生成归档草稿时使用所选思维模式。

归档草稿和版本记录生成时的思维模式。新增讨论或切换思维模式后，旧草稿必须重新生成才能确认；已确认版本与快照保持原样。JSON 备份和 Markdown 快照导出包含模式信息，旧 JSON 备份兼容恢复为默认模式。

维护者可以修改 skill 及其配套 Markdown，重新构建后生效。新增人物时，在 `skills/<目录>/` 提供 `SKILL.md` 和参考文件，并在 `src/thinking-modes.ts` 注册标识、名称、说明和 skill 目录。统一加载器按需加载所选目录的所有 Markdown，每次请求附带完整资料，不执行 skill 中的工具或文件访问指令。资料会增加请求输入长度；长度检查包含资料，加载失败会明确提示并保留对话。

## AI 配置

调用方式参考 `note-with-ai`：浏览器直接 `fetch`、Bearer 密钥、非流式回复；普通对话直接接收文本或 Markdown，兼容旧 JSON 回复格式；DeepSeek 归档使用只含标题和正文的 JSON 模式并关闭 thinking，MiniMax 归档使用 Markdown，沿用低 reasoning 与分离推理参数。

| 服务商 | 默认模型 | 接口 |
| --- | --- | --- |
| DeepSeek | `deepseek-flash` | `https://api.deepseek.com/chat/completions` |
| MiniMax 国内 | `MiniMax-M3.1-Flash` | `https://api.minimax.cn/v1/chat/completions` |

模型名称可在设置中修改。默认值沿用参考项目，模型可用性和浏览器直连 CORS 取决于服务商与账户；此实现未使用真实密钥验证线上模型。若服务商不支持浏览器跨域，当前无后端的范围内无法绕过其限制。

调用发送当前灵感的完整会话、最新方案及当前所选模式的资料。其它灵感、本地设置和备份不会附带到请求中。密钥放在 Authorization 头，不放入消息正文。AI 不自动归档或执行方案中的实际操作。

请求支持手动取消，90 秒超时，失败不会自动重试付费调用。发送前先保存用户消息；失败、取消或重开页面后可继续请求，不会重复追加原文。切换会话会中止旧请求，忽略迟到响应。有效的对话不会因为缺少归档字段被拒绝；可恢复 JSON 字符串中未转义的换行。空回复、缺失方案正文或输出截断时不保存结果。

## 本地数据

- React 19、TypeScript、Vite、lucide-react；原生 HTML 控件与自定义 CSS，不使用 construct-kit。
- `localStorage` 保存会话和设置，无后端、账号、云服务或跨设备同步。清除网站数据会删除记录，请定期下载 JSON 备份。
- 存储损坏时暂停写入，提供原始数据下载与有效备份恢复；空间不足时保留最新内容在页面内存并提示下载备份。
- 检测其它标签页的数据变化，并在每次写入前检查当前保存内容；发现冲突则暂停写入。建议在一个标签页中编辑，备份后刷新读取其它页面的修改。
- Markdown 使用安全的 React 渲染，不执行原始 HTML；远程图片显示为文字占位，避免自动请求外部资源。

## 代码与验证

- `src/types.ts`：持续会话、版本与快照类型。
- `src/data.ts`：存储校验、归档、版本编辑、备份恢复、Markdown 导出。
- `src/ai.ts`：服务商参数、提示词与请求生命周期；`src/ai-response.ts` 按对话/归档分别解析返回内容。
- `src/thinking-modes.ts`：模式注册与显示信息；`src/thinking-skills.ts`：Markdown 资料按需加载与模式提示词。
- `src/App.tsx`：工作台、持续会话与版本操作；`src/components/` 包含弹窗、设置、Markdown 与方案编辑器。
- `src/styles.css`：桌面布局与手机适配。

测试参考 `note-with-ai`，使用 Vitest、jsdom、React Testing Library 和 mock 请求，不使用 Playwright，也不调用真实付费 AI 服务。覆盖版本追加与编辑隔离、草稿确认、旧快照只读、持续对话、恢复冲突、密钥持久化选项、请求参数、错误、取消、超时与迟到响应。

## 回复格式修复

原校验强制每个操作同时返回 `reply`、`title`、`markdown`，会把只包含有效回复的结果误报为“AI 返回格式无效”。现按操作分别读取字段：对话只需要回复，归档只需要标题与正文；普通对话不再强制 JSON 包装。对应回归测试先复现了三种误拒绝，再验证修复；模型响应的空内容和截断仍明确报错。
